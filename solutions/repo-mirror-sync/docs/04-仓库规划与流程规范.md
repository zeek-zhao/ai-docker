## 1 范围

本文档规定本仓库（`ai-docker`）的目录结构规范、文档规范与流程规范，是所有入库内容与协作过程的规范基准。配套强制规则见根目录 `AGENTS.md`（对所有 AI Agent 会话全局生效）。

| 引用 | 用途 |

| AGENTS.md | Agent 全局硬性约束（脚本边界、临时脚本治理、诚实性） |

## 3 目录结构规范

### 3.1 目录树（规划基线）

```
ai-docker/
├── AGENTS.md                     # Agent 全局工作规范（全局生效）
├── README.md                     # 仓库入口：索引 + 决策参数 + 阶段状态
├── .gitignore                    # 版本控制边界
├── config/                       # ① 策略与配置区（唯一策略出处）
│   ├── scan.yaml                 #    扫描频率、请求上限、预算、仓库清单（scan.repos，ADR-013）、缓存保留策略（keep_blocks/keep_versions）
│   └── policy.yaml               #    块、组合、加密、选举规则、告警
├── tools/                        # ② 脚本区（全部正式脚本只允许在此）
│   ├── scan_inventory.py         #    低频扫描（唯一调 GitHub API 处）    [阶段 0/1]
│   ├── detect_drift.py           #    sha 比对漂移检测                  [阶段 3]
│   ├── plan.py                   #    选块 + 装箱                       [阶段 1]
│   ├── merge_guard.py            #    合并裁决 + 哈希去重               [阶段 3]
│   ├── notify.py                 #    告警投递网络层（唯一网络点）      [阶段 5]
│   ├── cache_gc.py               #    缓存 LRU 清理与预算审计          [阶段 5]
│   └── ctl                       #    统一入口：plan/build/push/fuse/verify [阶段 1]
├── docker/                       # ③ 镜像定义区                             [阶段 2]
│   ├── toolchain.Dockerfile      #    L0 固定 digest：git/age（ADR-011，挂载由消费侧承担）
│   ├── block.Dockerfile          #    参数化 BUILD_BLOCK
│   └── fused.Dockerfile          #    融合视图 + manifest 软链
├── .github/workflows/            # ④ 流水线区                        [阶段 2~5]
│   ├── scan.yml                  #    定时低频扫描 + 漂移检测 + 告警投递
│   ├── build-block.yml           #    可复用 workflow（输入 block id）
│   └── verify-fuse.yml           #    融合验收 + 缓存治理审计
├── docs/                         # ⑤ 文档区（ISO 规划文档族）
│   ├── 01-方案总览.md … 04-本文档
├── local/                        # ⑥ 临时脚本区（不入库，到期删除）
└── out/                          # ⑦ 运行产物区（不入库）
    ├── inventory.json / inventory.csv / plan.json
```

方括号标注为所属落地阶段（DSH-PLAN-001 §18）；未标注的文件已随本规划入库。

### 3.2 存放规则

| 内容类型 | 允许位置 | 禁止位置 |
|---|---|---|
| 正式脚本 | `tools/`、`.github/workflows/` | 仓库外任何路径；`docs/`；根目录散落 |
| 镜像定义 | `docker/` | — |
| 策略/阈值/选举规则 | `config/*.yaml` | 脚本内硬编码（尤其 5 GB / 4 GB） |
| 临时脚本/探针/调试 | `local/`（不入库） | 仓库其余任何位置入库 |
| 运行产物 | `out/`（不入库） | 入库 |
| 规划/规范文档 | `docs/`（编号管理） | 根目录（README/AGENTS 除外） |

### 3.3 版本控制边界（.gitignore 契约）

`out/`、`local/`、`tmp/`、`*.log`、`*.key`、`.env*`、`__pycache__/`、`.venv/` 永不入库；密钥与 token 一旦误入库视为安全事件，立即轮换并走 §5.6 事件流程。

## 4 文档规范

### 4.1 编号与命名

1. 文档编号规则 `DSH-PLAN-NNN`，与文件名 `docs/<两位序号>-<中文名>.md` 对应；新增文档顺延编号，已归档编号不复用。
2. 文件名使用中文（与交流语言一致），不含空格；代码/配置标识符用英文。

### 4.2 必备结构（ISO 条款风格）

每份正式文档必须包含，依序：

1. 文档元信息表（编号/版本/日期/状态/上位文档）；
2. 修订历史表；
3. `1 范围`；
4. `2 规范性引用文件`（区分规范性/资料性）；
5. `3 术语和定义`（或声明沿用 DSH-PLAN-001 §3）；
6. 正文章节（多级编号 4、4.1、4.1.1）；
7. 附录（资料性/规范性标注）。

### 4.3 版本与变更记录

1. 版本遵循 SemVer：结构调整/需求语义不兼容 → 升主版本；增补 → 次版本；勘误 → 修订号。
2. 任何变更在「修订历史」追加一行（版本/日期/说明），禁止删除历史行。
3. 内容变更涉及 FR/NFR、ADR、选举规则、预算参数时，先改文档与 ADR 再动实现（AGENTS.md §6）。

### 4.4 书写纪律

1. 禁止断言未执行的动作；未实现内容标注「待执行」并附所属阶段。
2. 禁止杜撰链接、图片与外部事实；引用需求方材料须注明来源。
3. 中文行文，条款编号后接句首大写或动词开头；表格优先于长段落。

## 5 流程规范

### 5.1 角色与职责

| 角色 | 职责 |
|---|---|
| 需求方 | 确认决策参数与重大变更；处置 `quarantine/` 隔离区 |
| 落地工程师 / AI Agent | 按阶段实现；遵守 AGENTS.md；维护文档与追溯 |
| 评审者 | 阶段验收（DSH-PLAN-003 §10）与重大变更评审 |

### 5.2 分支与提交

1. 分支模型：`main` 受保护（须评审后合并）；功能分支 `feat/<阶段>-<主题>`；文档分支 `docs/<主题>`。
2. 提交说明：Conventional Commits，`feat|fix|docs|chore|refactor(范围): 摘要`；范围 ∈ `scan/plan/build/fuse/alert/docs/config`。
3. 一次提交一个主题；涉及 FR/NFR 的提交须在正文附需求 ID 与（如适用）ADR 编号。

### 5.3 变更管理

1. **重大变更**（影响 FR/NFR、ADR、选举规则、预算参数、目录结构规范）：流程 = 提出_issue 或会话记录 → 更新文档与 ADR → 需求方确认 → 实现 → 验收记录。
2. **一般变更**（普通实现）：提交说明映射需求 ID 即可，无需需求方确认。
3. 策略值变更（`config/*.yaml`）：必须同步更新对应 ADR 与本文档 §3.1 基线引用，禁止「只改配置不改文档」。

### 5.4 临时脚本治理（对应 AGENTS.md §3.2）

1. 生命周期：`创建 → 使用 →（转正 或 到期删除）`；有效期 **7 天**，从文件名日期前缀起算。
2. 命名：`local/YYYYMMDD-<主题>.<ext>`（ISO 8601 紧凑日期）。
3. 转正：临时脚本验证的逻辑须改写为 `tools/` 正式实现（含配置化、日志、错误处理）后入库，临时件按期删除。
4. 集成环境（CI、自动化任务）禁止引用 `local/` 与 `out/` 之外的临时产物。

### 5.5 CI 门禁与产物治理

1. 每个 job 先跑 `ctl plan`，无 `plan.json` 不允许拉取/构建。
2. 融合验收门禁：manifest 软链唯一 + 哈希一致（失败即阻断）；registry 抽样确认无明文制品。
3. `out/plan.json` 每次运行归档（保留策略：≥ 90 天），供 H11 审计。

### 5.6 告警处置与事件流程

1. 四类告警（budget_exceeded / scan_error / drift_detected / cache_pressure）1h 节流、按 kind 聚合。
2. `drift_detected` → 仓库管理员执行 `repo sync --force-sync` 或刷新 mirror，处置结果回写 `inventory.json`。
3. 密钥泄漏类事件：立即轮换凭据 → 排查入库痕迹 → 记录事件报告（不入库敏感细节）。

### 5.7 评审与验收

1. 每落地阶段完成即对照 DSH-PLAN-003 §10 验收准则自检，结论记入相关文档修订历史。
2. 重大变更合并前须有一名评审者确认（AI Agent 不得自我评审重大变更）。

## 6 符合性检查清单（合并/提交前自检）

| # | 检查项 | 通过标准 |
|---|---|---|
| C1 | 脚本位置 | 全部在 `tools/`、`docker/`、`.github/workflows/` |
| C2 | 临时脚本 | `local/` 内且不入库；命名带日期；无到期未删文件 |
| C3 | 策略出处 | 阈值/频率/选举规则只出现在 `config/*.yaml` |
| C4 | 文档同步 | 涉及 FR/ADR/选举规则/预算的改动已更新文档与修订历史 |
| C5 | 追溯 | 提交说明含需求 ID；重大变更附 ADR |
| C6 | 诚实性 | 无「已验证/已生效」类未执行断言；未实现项标「待执行」+ 阶段 |
| C7 | 边界卫生 | `out/`、`local/`、`tmp/`、密钥未出现在暂存区 |
| C8 | 日期格式 | 文档与命名使用 ISO 8601 |

## 附录 A（资料性）

本规范与 AGENTS.md 的分工：AGENTS.md 面向「AI Agent 会话行为」的强制约束；本文档面向「仓库内容与协作过程」的完整规范。两者冲突时以 AGENTS.md 为准（其定位为全局生效的最高优先级规则），并应立即修订本文档消除冲突。
