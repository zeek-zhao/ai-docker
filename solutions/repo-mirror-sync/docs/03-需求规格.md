## 1 引言

### 1.1 目的
规定「repo 多仓分层镜像同步系统」的功能需求、非功能需求、接口与数据需求，并建立「原始诉求 → 需求条目 → 架构决策 → 落地阶段」的追溯关系，作为实现与验收的唯一需求基准。

### 1.2 范围
覆盖：体积清单扫描、计划编排、镜像分层构建、漂移检测与合并裁决、运行时融合验收、告警治理。不覆盖：mirror 仓库自身的运维、对象存储选型。

### 1.3 需求条目约定
每条需求含属性：**ID、描述、来源（R#/ADR#）、优先级（M=必须 / S=应该 / C=可以）、验收准则**。所有实现改动须在提交说明映射到本文档 ID（AGENTS.md §6）。

## 2 规范性引用文件

DSH-PLAN-001 §5 决策参数表；DSH-PLAN-002 §7 ADR 表。
资料性引用：ISO/IEC/IEEE 29148:2018、ISO/IEC/IEEE 12207:2017、ISO 8601-1:2019。

## 3 术语和定义

沿用 DSH-PLAN-001 §3（块、组合、清单、绑定表、漂移、选举规则、隔离区、size_class 等）。

## 4 总体描述

产品定位：在 GitHub Actions 单次 5 GB 存储上限内，把 manifest 管理下的 N 个仓库按 label/topic 切片为加密镜像块；支持「只拉自己开发的那一块」，支持多块运行时 OverlayFS 融合为跨目录全量视图；体积判断先于拉取；变化发现不依赖 manifest。

用户特征：开发者（日常按块取代码）、平台维护者（治理配额/缓存/告警）、仓库管理员（关注清单准确与漂移）。

约束：所有脚本在仓库内；临时脚本只进 `local/` 且到期删除；策略唯一出处 `config/*.yaml`；交付全层加密（D3）。

## 5 功能需求

### 5.1 扫描与清单（FR-S）

| ID | 描述 | 来源 | 优先级 | 验收准则 |
|---|---|---|---|---|
| FR-S1 | 低频扫描任务按 `every_days`（=7）周期运行，错开整点，单次请求数 ≤ `max_requests_per_run`（=200），预算耗尽保存 `cursor` 下次续跑 | R2/R4, ADR-002 | M | 人为截断运行后，cursor 存在且续跑不重复计费请求 |
| FR-S2 | 增量扫描：先取 HEAD sha 与基线比对，无变化仅更新 `last_scanned`，不重算体积 | R4 | M | 抽样验证无变化仓库该周期仅消耗 1 次 API 请求 |
| FR-S3 | 产出 `inventory.json` 全字段（DSH-PLAN-001 §7.2 字段表）并同步渲染 `inventory.csv` | R2 | M | 字段完整性校验通过；CSV 可被人工直接阅读 |
| FR-S4 | 体积按「`size_kb×1024` 上界估算 + `lfs_bytes` 单列」记录，`scan_status` 标注 `ok/pending/error/oversized` | R1/R4 | M | `oversized` 行数与非零 LFS 仓库数与人工抽查一致 |

### 5.2 计划与编排（FR-P）

| ID | 描述 | 来源 | 优先级 | 验收准则 |
|---|---|---|---|---|
| FR-P1 | 标签体系维护三个正交维度：`label`（人工）、`topic`（GitHub）、`size_class`（派生自动维护） | R3/R5, ADR-002 | M | 新导入仓库自动获得 size_class，人工维度不被覆盖 |
| FR-P2 | `ctl plan` 支持 `--block / --combo / --topics / --budget`，先输出计划再拉代码 | R2/R6 | M | 计划输出含仓库名单、预估体积、是否超限；预算参数生效可验证 |
| FR-P3 | 装箱采用 size_class 降序 FFD；约束：单块不可跨 job；共享目录块尽量同 bin | R7 | M | 构造用例下 FFD 结果与人工最优解一致或给出差距说明 |
| FR-P4 | 超预算单仓降级：`--filter=blob:none --depth=1` + `sparse-checkout`，镜像只含稀疏目录，全量历史留 mirror 冷备 | R1, ADR-009 | M | k8s 类用例单 job ≤ 预算，且冷备可回溯完整历史 |
| FR-P5 | 每次 plan 输出并归档 `plan.json`（含输入快照、算法版本、切分结果、超限原因） | H11 | M | 任取一次历史 plan 可复现当时决策依据 |

### 5.3 构建与分层（FR-B）

| ID | 描述 | 来源 | 优先级 | 验收准则 |
|---|---|---|---|---|
| FR-B1 | L0 工具链镜像（git/age/overlayfs）固定 digest；镜像索引 `manifest-index:<master-sha>` 用 SHA tag 非 `latest`，旧 tag 永久保留 | R12, ADR-004 | M | master 变更产出新 SHA tag 且旧 tag 可回指 |
| FR-B2 | 索引不进块镜像继承链：索引经 CI 产物 `manifest-index.tar` + 运行时卷提供；块镜像 FROM 工具链镜像 | R13, ADR-004 | M | manifest 高频变更下块镜像层缓存命中（CI 日志 CACHED） |
| FR-B3 | 每块构建产出 `bindings.json`（依赖 manifest 条目 path/rev/sha + digest）；重建范围 = manifest diff ∩ bindings | R14, ADR-001 | M | manifest 改 1 条目 → 仅命中块重建，其余块零重建 |
| FR-B4 | 交付镜像/制品**全层加密**（age）；镜像 tag = 明文内容 sha256（保持逻辑身份） | D3, ADR-007 | M | registry 中无明文制品；同内容两 tag 可交叉验证 |
| FR-B5 | 单块体积 ≤ `budget_bytes`（=4.0 GB）；超限自动走 FR-P4 降级并告警，不静默失败 | R1/R17, ADR-003 | M | 构造超限用例：job 降级 + 1 分钟内收到通知 |

### 5.4 漂移与合并（FR-D）

| ID | 描述 | 来源 | 优先级 | 验收准则 |
|---|---|---|---|---|
| FR-D1 | 漂移检测：上游真实 HEAD sha vs mirror 侧 `ls-remote` sha，只比 sha 不下载内容；结果写回 `inventory.json.mirror_sha` | R15, ADR-002 | M | 手动回退 mirror 1 个 commit，下一周期报 `drift` 且只补拉 1 块 |
| FR-D2 | 合并裁决固定顺序：先按 manifest 重建取得基线 → 后漂移补拉并校验 sha；不一致（mirror 落后）以 manifest 为准，补拉包进 `quarantine/` 隔离区，不进发布镜像 | R16, ADR-008 | M | 构造双到达用例：无双版本；隔离区含待人工确认包与合并日志 |
| FR-D3 | 内容级去重：合并前同路径文件算 sha256，一致则硬链，不一致按冲突矩阵处理 | R10 | S | 同内容文件物理仅一份（inode 级验证） |

### 5.5 运行时融合（FR-F）

| ID | 描述 | 来源 | 优先级 | 验收准则 |
|---|---|---|---|---|
| FR-F1 | 运行时 OverlayFS 融合：拉取→解密→`lowerdir` 挂载；单次融合 ≤ 8 层 | R8, ADR-001/007 | M | 单容器内可见全部所选 topic 目录 |
| FR-F2 | 冲突矩阵三类处理：A 类（同内容）保留一份；B 类（同路径不同内容）按 FR-F3 裁决；C 类（目录结构不同）默认 merged，可切严格隔离 | R9/R10 | M | 三类用例逐一验证，行为与矩阵一致 |
| FR-F3 | 选举规则唯一实现：`precedence = [toolchain, self-dev, k8s, edge]`；`manifest/**` pin toolchain；`**/.gitmodules` pin self-dev；`**/build.sh` isolate 前缀隔离；规则只读 `config/policy.yaml` | D5, ADR-005 | M | pin 路径软链解析唯一；isolate 路径两份内容并存不覆盖 |
| FR-F4 | manifest 唯一权威：融合前置 `/authority/manifest`（去写权限），各层 `manifest` 删除并软链；CI 门禁校验软链唯一 + `manifest.xml` 哈希与 `manifest.sha` 一致，失败即阻断 | R11 | M | 故意放置第二份 manifest → 校验失败阻断 |
| FR-F5 | 布局混合：self-dev 单块扁平（`repo sync` 友好），跨 topic 组合前缀；由 `overlay.layouts` 配置切换 | D4, ADR-006 | S | 两种布局用例均通过目录可达性验收 |

### 5.6 告警与治理（FR-A）

| ID | 描述 | 来源 | 优先级 | 验收准则 |
|---|---|---|---|---|
| FR-A1 | 四类告警（budget_exceeded / scan_error / drift_detected / cache_pressure）接入 github-issue + feishu-webhook，`throttle=1h`，按 kind 聚合 | H10/R17, ADR-010 | M | 人为制造超限，1 分钟内收到单条可行动通知 |
| FR-A2 | 缓存预算：`cache_gb` 控制；构建后按 LRU 只保留最近 N 块 × 2 版本；加密层进 artifacts 不进 cache | H1, ADR-007 | M | 缓存占用峰值 ≤ `cache_gb`；超限清理有日志 |
| FR-A3 | API 限流防护：`max_requests_per_run` + cursor 续跑 + 先比 sha 再算体积 + fine-grained 多 token 轮转 | H2 | M | 模拟限流场景：任务分批完成，无静默丢仓 |

## 6 非功能需求（NFR）

| ID | 描述 | 度量/验收 | 优先级 |
|---|---|---|---|
| NFR-1 | 配额经济性：日常 CI 零 GitHub API 消耗（只读 inventory） | CI 日志无 API 调用 | M |
| NFR-2 | 计划时延：绑定表 diff 毫秒级（800 仓 manifest）；plan 先于任何拉取动作 | diff 耗时 < 1s；无 plan 无拉取 | M |
| NFR-3 | 可审计性：策略唯一出处 `config/*.yaml`；`plan.json` 长期归档；ADR 记录所有重大决策 | 抽查任一历史决策可还原依据 | M |
| NFR-4 | 安全性：交付边界全层加密；密钥/token 仅环境变量；密钥不入库不入日志 | 加密制品抽样解密验证 + 仓库扫描无密钥 | M |
| NFR-5 | 可回滚性：镜像 tag（master SHA / 明文内容 sha256）永久保留可回指 | 任选历史 tag 可重新拉取 | S |
| NFR-6 | 判断保真：体积告警同时给「估算/实测」双数；`oversized` 强制稀疏检出 | 告警样例含双数字 | S |
| NFR-7 | 兼容性：self-dev 扁平布局 + manifest 唯一权威，`repo sync` 行为不受融合影响 | 扁平布局内 `repo sync` 用例通过 | S |

## 7 外部接口需求（IF）

| ID | 接口 | 需求 | 关联 |
|---|---|---|---|
| IF-1 | GitHub REST API | 仅扫描/漂移子系统调用；受 FR-S1/S2 与 FR-A3 约束；fine-grained token | FR-S1/A3 |
| IF-2 | git 协议（mirror `ls-remote`） | 漂移检测只读远端引用，不下载对象 | FR-D1 |
| IF-3 | 容器 registry（GHCR 或等效） | 存取加密镜像；tag 规范见 FR-B1/B4 | FR-B1/B4 |
| IF-4 | 对象存储 | `manifest-index.tar` 与加密冷备（mirror `--mirror` 全量历史） | FR-B2/P4 |
| IF-5 | 告警通道（GitHub Issues + 飞书 webhook） | FR-A1 的两类 channel；凭据环境变量注入 | FR-A1 |

## 8 数据需求

1. `inventory.json` 字段集以 DSH-PLAN-001 §7.2 为准，新增字段须回改该表并升版本。
2. `bindings.json` 结构：`{block, repos:[{path, rev, sha}], digest}`（DSH-PLAN-001 §11.3）。
3. `plan.json` 必须含：输入 inventory 快照引用、policy 版本、bins 明细、超限原因（FR-P5）。

## 10 验收准则汇总（按阶段）

| 阶段 | 验收 = 通过条件 | 关联需求 |
|---|---|---|
| 0 基线 | 能回答：哪些仓库 >1.5GB、>3.5GB、self-dev 标签占比 | FR-S1~S4 |
| 1 计划器 | `plan --combo full-reading` 自动拆出不超预算 job 列表 | FR-P1~P5 |
| 2 索引层与块镜像 | manifest 改 1 仓 → 仅 1 块重建，其余 CACHED；registry 无明文制品 | FR-B1~B5 |
| 3 漂移与合并 | mirror 回退 1 commit → 下一周期报漂移且只补拉 1 块；双到达用例无双版本 | FR-D1~D3 |
| 4 融合与验收 | 单容器可见全部 topic；manifest 软链唯一；不同 `build.sh` 隔离非覆盖；解密挂载成功 | FR-F1~F5 |
| 5 告警与治理 | 人为超限 → 1 分钟内单条可行动通知；缓存峰值 ≤ `cache_gb` | FR-A1~A3 |
