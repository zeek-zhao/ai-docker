# TD-005 任务书：Magpie API 端口 Bug 核查与 DSH 403/插件获取排障

> 文档编号：TD-005 · 版本：v1.0 · 日期：2026-11-28 · 作者：zeek.zhao（AI） · 评审：需求方 · 状态：已完成

## 1. 任务来源与问题

需求方报告两项（分支：ai-devbox）：

1. Magpie API Bug 说明：`magpie web --gateway` 网页与 API 网关共用同一地址端口时，网页抢占端口，`/v1/chat/completions` 等被网页登录页拦截；规避方式为端口分离（网关 3425 / 网页 3430）。要求排查当前部署。
2. 新报错：`dsh client api: directoryPicker/list failed: transport failure for /api/directoryPicker/list: HTTP 403`，且 DSH 插件无法获取；要求侧重网络/端口/代理方向根因分析。

## 2. 排查结论

### 2.1 问题①（Magpie 同端口抢占）——当前部署不成立

- 实际进程：`magpie web --addr 127.0.0.1:3430 --no-open --gateway`——自 M7 起网页(3430)与网关(3425)**已分离**。
- 实测网关 3425：`GET /v1/models` → 200 JSON；`POST /v1/chat/completions`（无效模型）→ 404 JSON 业务应答——均为网关应答，**非登录页拦截**。

### 2.2 问题②（dsh 403）——根因：dsh fence 独立 Origin 校验层

排查矩阵（经网关，双 cookie：auth-gate + dsh 会话）：

| 请求形态 | 结果 |
|---|---|
| 无 Origin/Referer | 401（无会话）/ 404（有会话） |
| + Origin `http://10.22.67.213:8080`（浏览器入口） | **403 forbidden**（serverInfo/directoryPicker/plugins 全部） |
| + Origin `http://127.0.0.1:3081`（精确 listen origin） | 过校验（404 路由级） |
| Origin localhost:3081 / https 变体 | 全 403 |

**结论**：`dsh web` 的 browser-trust fence 除 Cookie 校验（`--trusted-host`，M7 D12 已解）外，还有**独立的 Origin 白名单校验，白名单=精确 listen origin；`--public-url`/`--trusted-host` 不参与**。反代场景浏览器 XHR 自动携带公网入口 Origin → 全部 403 → UI「插件无法获取」、桌面 client `directoryPicker/list` transport failure 403。与"只暴露一个端口"无关。

补充澄清：`directoryPicker/list` 路由在 web 版不存在（index bundle 无引用；属 dsh client-modules 桌面功能 API）——桌面 client 远程连 web 版的该调用在 403 修复后变为 404，仍是"web 版不支持"，但不再是 fence 拒绝。

## 3. 修复（D17）

`config/caddy/Caddyfile` dsh 反代块新增 `header_up Origin http://127.0.0.1:3081`（Origin 同源化为 listen origin；Cookie 校验仍由 Host/X-Forwarded-Host + trusted-host 承担）。
