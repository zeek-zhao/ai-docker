## 2. 技术决策记录

| # | 决策 | 依据 |
|---|---|---|
| D11 | DSH 采用 npm `@deepseek-ai/dsh@0.2.2-rc.5`（npmmirror，与快照同版本）；构建期 `--allow-scripts=@deepseek-ai/dsh-subprocess-local,koffi,node-pty,protobufjs`（npm 新版默认拦截 install-scripts，node-pty/koffi 为原生模块必须编译） | 快照版本锚定 |
| D12 | dsh web 加 `--public-url`（DSH_PUBLIC_URL，感知 /dsh 前缀）+ `--trusted-host`（从 PUBLIC_URL 解析 authority）。实证链：Caddy 强制注入 X-Forwarded-Host=客户端入口 Host（header_up 对 X-Forwarded-* 免疫），dsh fence 校验 XFH ∈ {listen}∪trusted-host；另：fence 实例须在 Caddy 就绪后启动（entrypoint 早期启动的实例 fence 异常 401，复现于重启；同参数后启动正常）→ entrypoint 尾部 Caddy 先行→curl 轮询→start_dsh | 容器内假上游抓包 + 对照矩阵（3081 vs 3083/3084/3085/3087） |
| D13 | magpie 采用 magpie-cli-linux-amd64 v0.1.4984（github.com/yetone/magpie release，需求方指定渠道；仅 .zip 无 tar.gz）；`MAGPIE_WEB_KEY`（16+ 字符，默认 devbox-magpie-key）+ `MAGPIE_WEB_URL`（感知 /magpie 前缀）；单进程 `magpie web --addr 127.0.0.1:3430 --no-open --gateway` 同起面板 3430 + 网关 3425 | release 资产实测 |
| D14 | 凭证零处理（需求方：登录时云端导入）；快照 7 份配置以脱敏骨架入库（真实 key 运行时人工/云端导入）；magpie gateway.json 为运行态状态文件不铺 | Q2 确认 + R11 红线 |
| D15 | 删除 `forward_auth { copy_headers Cookie }`——auth-gate /verify 响应无 Cookie 头，该指令把发往上游请求的 Cookie 头清空 → dsh/magpie 收不到自身会话 Cookie 而 401；客户端 Cookie 由 reverse_proxy 默认透传 | 直连 3081 全链 200 vs 经主 Caddy 401 的差异定位 |
| D16 | magpie 面板 XHR 用绝对路径 `/api/*`（不带 /magpie 前缀）落入 homepage Next.js → 404（access log 实证 12+ 条）。修复：`@magpie_api { path /api/*; header_regexp Referer "/magpie(/|$)" }` 按 Referer 分流至 3430；homepage 自身 /api/*（Referer 首页路径）不受影响 | Caddy access log + 浏览器复测 |
| D17 | desktop 档案为 Electron 应用专属（`dsh --profile desktop web` 报 managed exclusively by the Electron application）；CLI 一律默认 web profile；desktop 档案保留镜像内供云端导入参考 | dsh CLI 报错原文 |
| D18 | magpie 插件 workspace 用 bun install（快照工作流）；page-free-tokens 本地 tgz 依赖剔除（未随快照提供，插件本为 off；需求方：自行研究依赖） | Q3 确认 |
