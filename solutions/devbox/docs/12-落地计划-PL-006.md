## 1. 里程碑任务与结论

### T10.1/T10.2 插件迁移 web 版（D26）
- 根因：见 TD-006 §4。
- 修复（提交 c46cb5a → 8b5dce3 → 8ab4794 → 5aa3d25 → 909567d）：
  1. 构建期 `jq del dsh-at-file`（剔除私有 peer 链，22 插件保留）；
  2. `pnpm install --allow-build=koffi,node-pty,protobufjs,esbuild,@swc/core`（v12 唯一生效形态）+ 失败即断（日志尾显+node_modules 存在性校验）；
  3. 产出双模板：desktop（`/etc/skel/.dsh/profiles/desktop/`）+ web（`/opt/devbox-skel/web-profile/`）；
  4. entrypoint 首启播种：web profile 缺失时 `mv` 模板至 `~/.dsh/profiles/web` 并 chown dev。
- 启动退出排障：22 插件使 dsh web 初始化 >3s，token URL 迟出；`grep` 空匹配在 `set -euo pipefail` 下退出整个 entrypoint（Exited(1)）——改为轮询等待（最多 30s）+ `|| true` 兜底（提交 909567d）。
- dash 兼容两连败：`set -o pipefail`（c46cb5a F）与 `ERR_PNPM_IGNORED_BUILDS`（8b5dce3 F、8ab4794 F）。

### T10.3/T10.4 Magpie「网络问题」（D18）
- 根因：magpie 对写类 API（POST 安装/更新/设置）校验 Origin/Referer 须为自身 listen origin（403 "magpie's API answers magpie's own page only"）；反代场景浏览器 Origin 为公网入口 → 403，前端显示为「网络问题」。GET 类不触发，故市场浏览/Providers 正常（此前 M7 验收盲区）。
- 修复（提交 91f0fe0）：Caddyfile magpie 两反代块（`handle_path /magpie/*` 与 `@magpie_api`）均加 `header_up Origin http://127.0.0.1:3430` + `header_up Referer http://127.0.0.1:3430/`（分流 matcher 读原始请求，改写不影响 D16）。
- 验证：容器内 `caddy validate` Valid configuration；eval 重放 `POST /api/plugins/update` 200、`POST /api/update/using` 204；UI「Update all (1)」实测成功（待更新计数清零无报错）；`/api/*` 无 Referer /magpie 时仍 404（与 homepage 隔离保持）。
