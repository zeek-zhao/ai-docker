# TD-007 任务书 —— M11：web profile 插件更新修复、Magpie→DSH 供给链路与版本自动匹配

> 文档编号：TD-007 · 版本：v1.0 · 日期：2026-11-28 · 作者：zeek.zhao（AI 维护） · 状态：已交付

## 1. 范围

承接 M10 终态（镜像 20261128-1734），处理需求方报告的三项问题：
1. web profile 插件更新失败（「profile 声明了这些插件，但它们没有安装：dsh-at-file」）；
2. Magpie 中不显示 agent（打通 Magpie→DSH 的 API 与 MCP 供给链路）；
3. 插件与版本升级自动匹配机制（输入插件名+DSH/Magpie 目标版本即自动匹配，默认兼容相邻小版本升级）。

## 2. 需求方输入与确认

- m02571 原始报告三项；其中 pnpm「Switching to the store…requires purging and reinstalling the whole node_modules」提示的处理方式（是否全量重装）由 AI 评估后给建议（见 PL-007 §4 决策 D27）。

## 3. 根因（侦察结论）

| # | 症状 | 根因 |
|---|------|------|
| 1 | 更新流报「dsh-at-file 没有安装」 | M10 构建期只删了 dependencies，`dsh.profile.bundles` 数组仍声明 dsh-at-file → dsh 启动 skip+更新流校验失败 |
| 2a | llm-pi-ai patch 未激活 | M7 快照脱敏把 `maxTokensField` 换成字面 `<REDACTED>`→我方首次修复误填 `max_output_tokens`，而 schema 枚举仅允许 `max_completion_tokens`/`max_tokens` → ValidationError → **Magpie provider 从未装上（「不显示 agent」根因）** |
| 2b | better-sidebar 无法加载 | 上游依赖树内 `@deepseek-ai/dsh-typert-protocol` 导出漂移（无 `principalOf` 导出），import 即 SyntaxError |
| 3 | 无自动匹配手段 | 人工固定版本号；插件 peer 有三种形态（核心库 range/宿主白名单/无声明）未统一解析 |

## 4. 交付

- D27：bundles 与 dependencies 同步剔除（构建期 jq 链）；cordis.patch.yml `maxTokensField:"max_tokens"`；模板 `.npmrc store-dir` 固定 store（消除全量重装诱因，建议不采用 purge）；entrypoint 导出 `MAGPIE_GATEWAY_KEY`；升级 dsh-tui 0.20.2。
- D27 补充：better-sidebar 从 bundles/dependencies/patch 三处剔除（上游导出漂移，修复后恢复）。
- D28：`tools/plugin-version-match.sh`（npm view 逐版本 peerDependencies 判定；从最新往回首个兼容即停；三种 peer 形态全覆盖；--json 矩阵；入镜像 /usr/local/share/devbox/tools/）。
